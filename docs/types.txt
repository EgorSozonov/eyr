TOTAL OVERHAUL OF TYPES!

Store all types as full expressions with type parameters changed into De Bruijn indices, and in
forward Polish Notation!




Format of numbers in @types:

3 bits: sort of item.
if 000: it's a concrete type and the next 29 bits are its TypeId

ei 001: [DOUBLET] it's a type call, next 29 bits are its Type Id,
        and the next Int is (8 bits of tyrity, 24 bits length (in ints) of the following subtree)
ei 010: [DOUBLET] it's a function, next 29 bits are 0,
        and the next Int is (8 bits of (arity + return type count)), 
           24 bits length (in ints) of the following subtree);
ei 011: [DOUBLET] it's a pointer ... (future releases);
ei 100: [DOUBLET] it's a nullable pointer ... (future releases);
ei 101: it's a type parameter and the next 29 bits are its de Bruijn index.

Examples:

Int will be 0x0.

[Foo Int] will be (001 then Foo's typeId)(00000001 then 1)(0 which is Int's typeId)

[F Str -> [Foo Int]] will be:

   (010 then 0)(00000010 then 4)
   (4 which is Str's typeId)(001 then Foo's typeId)(00000001 then 1)(0 which is Int's typeId)

$E will be (101 then 2 or whatever its de Bruijn index is in the current type expression)
